Bashing

This isn't a beginner Bash refresher. This is the practical stuff you actually use when writing scripts that should behave, stay readable, and not blow up because of weird quoting or sloppy variable handling. Solid patterns, real tricks, and the kind of Bash that lets you work fast without fighting the shell.

1. Variables & Expansions 
# Basic assignment (no spaces)
v="payload"

# Upper/lower casing
echo ${v^^}     # PAYLOAD
echo ${v,,}     # payload

# Substring extraction
key="abcd1234xyz"
echo "${key:4:4}"      # 1234

# Strip prefix / suffix
f="/var/log/auth.log.1"
echo "${f##*/}"        # auth.log.1
echo "${f%.log*}"      # /var/log/auth

# Default fallback
echo "${USER:-unknown}"

# Indirect expansion
cmd="ls"
ref="cmd"
echo "${!ref}"         # expands to ls

# Length of variable
echo "${#key}"         # 11

# Replace patterns inside variables
path="/tmp/stuff/drop.sh"
echo "${path/stuff/safe}"

Why this matters:

  • Cleaner logic without external tools
  • Less reliance on awk/sed for simple text work
  • Indirect references and slicing solve a lot of “I need part of this string” tasks
  • Default values prevent scripts from breaking on unset variables

Once you get comfortable with expansions, Bash becomes way more expressive and predictable.

3. Conditionals (if / test) 
# Basic structure
if [[ -f "/etc/passwd" ]]; then
    echo "file exists"
fi


# Checking exit codes
output=$(some_command)
if [[ $? -ne 0 ]]; then
    echo "command failed"
fi


# Numeric comparisons
x=10
if (( x > 5 )); then
    echo "x is greater"
fi


# String comparisons
name="john"
if [[ "$name" == "john" ]]; then
    echo "match"
fi


# Compound conditions
if [[ -d /tmp && -w /tmp ]]; then
    echo "/tmp is writable"
fi


# Negation
if [[ ! -s file.txt ]]; then
    echo "empty or missing"
fi


# Case statement (clean branching)
case "$1" in
    start) echo "starting..." ;;
    stop)  echo "stopping..." ;;
    *)     echo "usage: start|stop" ;;
esac


# Testing commands directly
if some_command; then
    echo "ok"
else
    echo "failed"
fi


# Short one-liners
[[ -z "$var" ]] && echo "empty"
[[ -n "$var" ]] || echo "still empty"

Why this matters:

  • Conditionals are the backbone of clean Bash scripting
  • Exit code handling separates “toy scripts” from real ones
  • Case statements keep your logic readable
  • Short-form conditionals speed up quick scripting work

Everything here is idiomatic, predictable Bash - the stuff worth building on.

4. Loops (for / while) 
# Basic for-loop (the one everyone actually uses)
for f in *.log; do
    echo "found: $f"
done


# Loop over a list of items
items=("alpha" "beta" "gamma")
for i in "${items[@]}"; do
    echo "$i"
done


# Loop with command substitution (classic pattern)
for user in $(cut -d: -f1 /etc/passwd); do
    echo "$user"
done


# C-style loop
for ((i=0; i<5; i++)); do
    echo "i = $i"
done


# While loop (stream processing)
while read line; do
    echo "line: $line"
done < file.txt


# While true loop (watch / poll something)
while true; do
    date
    sleep 1
done


# Loop over directories safely
for dir in */; do
    echo "dir: $dir"
done


# Loop with pattern matching inside
for f in *.txt; do
    [[ $f == *report* ]] && echo "report file: $f"
done


# Loop with break / continue
for x in {1..10}; do
    [[ $x -eq 5 ]] && continue
    [[ $x -eq 9 ]] && break
    echo "$x"
done

Why this matters:

  • Loops are the backbone of any real Bash script
  • The patterns above cover 99% of real-world use cases
  • Using arrays + safe quoting prevents weird bugs
  • While-loops are perfect for reading files or streams

Clean, predictable loops = maintainable Bash. This is the style worth sticking to.

5. Arrays 
# Declare an array
nums=(10 20 30 40)

# Access elements
echo "${nums[0]}"
echo "${nums[3]}"

# Length of array
echo "${#nums[@]}"

# Append items
nums+=("50" "60")

# Loop through array (the correct way)
for n in "${nums[@]}"; do
    echo "value: $n"
done

# Indexed loop
for i in "${!nums[@]}"; do
    echo "index $i -> ${nums[$i]}"
done

# Split a string into an array
line="alpha beta gamma"
read -r -a arr <<< "$line"
echo "${arr[@]}"

# Copy an array
copy=("${nums[@]}")

# Slice an array (Bash ≥ 4)
echo "${nums[@]:1:2}"    # start:1 length:2

# Associative arrays (key-value)
declare -A colors=(
    [error]="red"
    [ok]="green"
    [warn]="yellow"
)

echo "${colors[error]}"

# Loop associative array safely
for key in "${!colors[@]}"; do
    echo "$key => ${colors[$key]}"
done

Why this matters:

  • Arrays make scripts cleaner and easier to extend
  • Associative arrays let you build mini lookup tables
  • Slicing and copying arrays helps with structured data
  • Correct quoting avoids split bugs that plague weak Bash code

This is the level where Bash starts feeling like a real language instead of a mess of one-liners.

6. Redirection & Piping 
# --- Basic redirection ---
cmd > out.txt          # overwrite
cmd >> out.txt         # append
cmd 2> err.txt         # errors only
cmd &> all.txt         # stdout + stderr (Bash only)

# --- Silence commands completely ---
cmd >/dev/null 2>&1

# --- Pipe chaining (the real daily stuff) ---
cat logs.txt | grep "ERROR" | sort | uniq
ls -l | awk '{print $9, $5}' | column -t

# --- Redirect input ---
sort < file.txt
wc -l < file.txt

# --- Combine input + output ---
grep "foo" < input.txt > matches.txt

# --- Redirect multiple streams ---
make > build.log 2>&1

# --- Group commands and redirect once ---
{
    echo "start"
    date
    ls -l
} > snapshot.txt

# --- Read from a process (process substitution) ---
diff <(ls /etc) <(ls /usr)

# --- Feed a command into another without tmp files ---
printf "%s\n" "alpha" "beta" | tee list.txt | wc -l

# --- Use tee to split output (inspect + save) ---
cmd | tee debug.txt
cmd | tee -a history.log     # append mode

# --- Redirect in loops without messing them up ---
while read x; do
    echo "line: $x"
done < input.txt

Why this matters:

  • Pipes let you chain small commands into clean, readable workflows
  • Process substitution removes the need for temp files
  • Grouping avoids ugly redirect repetition
  • tee is perfect when you need output both on-screen and saved
  • Proper redirection keeps loops predictable

This is where Bash starts feeling powerful instead of primitive - once you get redirection right, everything else becomes easier.

7. Functions 
# Basic function (modern syntax)
hello() {
    echo "hello"
}
hello


# Function with arguments
greet() {
    echo "hi $1"
}
greet "world"


# Multiple parameters
sum() {
    echo $(( $1 + $2 ))
}
sum 4 9


# Return codes vs returned output
# (Bash doesn't 'return values', it prints them)
get_user() {
    echo "$USER"
}
u=$(get_user)
echo "user = $u"


# Named local variables (important for clean scripts)
calc() {
    local a=$1
    local b=$2
    echo $((a * b))
}

calc 3 7


# Functions calling functions
log() {
    echo "[log] $1"
}

task() {
    log "running task"
}
task


# Detect missing arguments (good practice)
require() {
    [[ -z "$1" ]] && {
        echo "missing argument"
        return 1
    }
}
require foo


# Functions as small reusable commands
exists() {
    [[ -e "$1" ]]
}

if exists "/etc/passwd"; then
    echo "ok"
fi


# Function library style
timestamp() {
    date "+%Y-%m-%d %H:%M:%S"
}

echo "Started: $(timestamp)"

Why this matters:

  • Functions keep Bash scripts readable instead of a wall of commands
  • Local variables prevent accidental cross-contamination
  • Argument handling makes scripts predictable
  • Chaining functions gives structure to longer scripts

This is the level where Bash stops being a pile of one-liners and becomes an actual tool you can build on.

8. Parameter Expansion Tricks 
# --- Default values ---
echo "${var:-default}"      # use default if var is empty or unset
echo "${var:=default}"      # assign default into var if empty
echo "${var:+alt}"          # use alt if var is set (rare but useful)

# --- String slicing ---
text="ABCDEFGHIJ"
echo "${text:0:3}"           # ABC
echo "${text:3:4}"           # DEFG
echo "${text: -2}"           # IJ  (note space before -2)

# --- Strip prefix/suffix ---
path="/usr/local/bin/script.sh"
echo "${path##*/}"           # script.sh      (strip longest prefix)
echo "${path#*/}"            # usr/local/bin/script.sh

echo "${path%.sh}"           # script without .sh
echo "${path%%/*}"           # empty (first slash removes entire path)

# --- Replace text inside variables ---
line="error: something happened"
echo "${line/error/warn}"    # warn: something happened
echo "${line//e/X}"          # replace ALL e → X

# --- Get length of variable ---
id="abc123"
echo "${#id}"                # 6

# --- Indirect reference (lookup by name) ---
cmd="ls"
ref="cmd"
echo "${!ref}"               # expands to ls

# --- Remove chars from both ends ---
trim="   hello   "
echo "${trim#"${trim%%[! ]*}"}"   # left trim
echo "${trim%"${trim##*[! ]}"}"   # right trim
# (This looks crazy, but it's pure Bash and works everywhere)

# --- Safe parameter expansion in loops ---
files=(file1 file2 "weird name")
for f in "${files[@]}"; do
    echo "$f"
done

# --- Test if variable is empty/unset ---
[[ -z "${var:-}" ]] && echo "empty"
[[ -n "${var:-}" ]] && echo "set"

Why this matters:

  • Default expansions prevent scripts from breaking on missing variables
  • Prefix/suffix removal is cleaner than using cut or awk
  • Slicing lets you parse text without external tools
  • Replace operations are faster and cleaner than calling sed
  • Indirect expansion gives you dynamic variable names when needed

Once you know this section well, 70% of “awk/sed hacks” become unnecessary.

9. Process Control (&, disown, nohup) 
# Run in the background
command &

# Bring background job back to foreground
fg

# List background jobs
jobs

# Detach a job so it keeps running after the terminal closes
command &
disown

# Keep a command running even if you log out (no hangup)
nohup command > out.log 2>&1 &

# Run several commands in the background and wait for them
task1 &
task2 &
wait         # waits for all background tasks to finish

# Run something on an interval
while true; do
    echo "tick"
    sleep 5
done &

# Limit CPU usage using nice (lower priority)
nice -n 10 long_task

# Cooperative parallelism using subshells
(
    echo "job A start"
    sleep 2
    echo "job A done"
) &

(
    echo "job B start"
    sleep 1
    echo "job B done"
) &

wait

# Redirect stdout and stderr when running in background
long_script.sh >logs/out.log 2>logs/err.log &

# Check if a process is running
if pgrep "myapp" > /dev/null; then
    echo "running"
fi

# Stop a background job politely
pkill -TERM myapp

Why this matters:

  • Backgrounding tasks lets you run long scripts without blocking the terminal
  • nohup is the classic way to keep a job alive after logout
  • disown detaches jobs cleanly without affecting the shell session
  • wait is essential when running parallel tasks
  • Good process control keeps scripts predictable and prevents runaway tasks

This is the part of Bash people ignore until they actually need reliability. Once you get these patterns down, writing long-running or multi-task scripts becomes easy.

10. One-Liners (Practical Bash Power Moves) 
# List largest files in current dir
du -ah . | sort -h | tail

# Find files changed in the last hour
find . -mmin -60 -type f

# Count lines, words, bytes for every file
for f in *; do echo "$f: $(wc -l <"$f") lines"; done

# Watch a command run every second
watch -n1 'date; ls -l'

# Inline JSON pretty-print
cat data.json | jq .

# Extract only the first column from a file
awk '{print $1}' file.txt

# Show file tree with sizes
find . -type f -printf "%10s %p\n" | sort -n

# Rename all .txt → .bak
for f in *.txt; do mv "$f" "${f%.txt}.bak"; done

# Replace spaces with underscores in all filenames
for f in *" "*; do mv "$f" "${f// /_}"; done

# Create a timestamped backup of a file
cp config.yaml config.yaml.$(date +%s)

# Simple progress bar for long loops
for i in {1..10}; do
    printf "\rstep %d/10" "$i"
    sleep 1
done; echo

# List unique file extensions
for f in *.*; do echo "${f##*.}"; done | sort -u

# Print only lines that contain numbers
grep -E '[0-9]' file.txt

# Quick inline sort + unique + count
sort data.txt | uniq -c | sort -nr

# Show top 10 most common words in a file
tr -cs 'A-Za-z' '\n' < file.txt | tr 'A-Z' 'a-z' | sort | uniq -c | sort -nr | head

# Remove empty lines from a file
grep -v '^[[:space:]]*$' file.txt

# Display only lines longer than 60 chars
awk 'length > 60' file.txt

Why these one-liners matter:

  • You don't need Python for half your small tasks
  • Chaining commands becomes natural once you see patterns
  • Quick parsing saves time and keeps your workflow tight
  • These cover 90% of “I need to inspect/clean/transform something fast” needs

One-liners are where Bash shines - small, sharp tools chained together to get work done quickly.

12. Secure IR Scripting Patterns 
# --- 1. Always copy evidence before touching it ---
src="suspect.bin"
dst="evidence/suspect.bin.$(date +%s)"
cp --preserve=all "$src" "$dst"


# --- 2. Never loop over unquoted variables ---
# Safe:
for f in *.log; do
    echo "$f"
done

# Unsafe:
# for f in $files; do ...


# --- 3. Always check exit codes before continuing ---
if ! output=$(some_command); then
    echo "failed: some_command"
    exit 1
fi


# --- 4. Build temporary workspace safely ---
tmpdir=$(mktemp -d)
cp "$src" "$tmpdir/"
# use $tmpdir freely
rm -rf "$tmpdir"     # cleanup when done


# --- 5. Use read -r for reliable line handling ---
while read -r line; do
    echo "line: $line"
done < file.txt


# --- 6. Avoid destructive wildcards ---
rm -- "$file"      # safe
# NEVER: rm $file  (unquoted expansions = disaster)


# --- 7. Use set -euo pipefail for strict mode ---
set -euo pipefail
# -e: exit on error
# -u: fail on undefined variable
# -o pipefail: catch pipeline failures


# --- 8. Log actions with timestamps ---
log() {
    printf "[%s] %s\n" "$(date '+%F %T')" "$*"
}

log "starting analysis"
log "copying files"


# --- 9. Use arrays for structured targets ---
targets=(/var/log /etc /opt/app)
for dir in "${targets[@]}"; do
    echo "checking $dir"
done


# --- 10. Write non-destructive filters first, act second ---
matches=$(grep -Rl "pattern" /path)
# only then:
#    do something with $matches


# --- 11. Confirm actions interactively when needed ---
read -p "Proceed with cleanup? (y/N) " ans
[[ $ans == y ]] || exit 0


# --- 12. Use traps for cleanup on exit ---
tmp=$(mktemp -d)
trap 'rm -rf "$tmp"' EXIT

# do work in $tmp

Principles behind these patterns:

  • Never modify or delete anything without a safe copy
  • Always quote variables - always
  • Fail early instead of running half-broken
  • Use temporary workspaces so you don't trash the system
  • Log everything so you know what the script actually did
  • Strict mode catches subtle bugs before they cause damage

This is the Bash you write when you're being careful, methodical, and want scripts that don't surprise you later.
